# Student Finance

แอปการเงิน Android ด้วย React Native/Expo และ Express เชื่อม MySQL ฐานข้อมูล `ip_std6730202092` ที่มีอยู่บนเซิร์ฟเวอร์ และจัดการผ่าน phpMyAdmin ที่ `nindam.sytes.net/nindamdb/`

## การเชื่อมต่อ

Frontend → `http://119.59.102.161:3012/api` → Backend → MySQL

phpMyAdmin เป็นหน้าจัดการฐานข้อมูล ไม่ใช่ URL สำหรับเชื่อม MySQL แอปใช้ mysql2 เชื่อมฐานข้อมูลจริงด้วย DB_HOST, DB_PORT, DB_USER และ DB_PASSWORD จาก `.env` เดิม โดยกำหนดฐานข้อมูลเป้าหมายเป็น `ip_std6730202092` ใน server.js ไม่แก้ไขไฟล์ `.env`

ไม่มีการอ่านหรือนำเข้าไฟล์ .sql ไม่มีคำสั่งสร้าง/แก้โครงสร้างตาราง และไม่ต้องรัน setup เซิร์ฟเวอร์ตรวจว่ามีตารางการเงิน 7 ตารางก่อนเปิดให้บริการ

## เริ่มบนเซิร์ฟเวอร์

นำไฟล์ Backend ที่แก้แล้วขึ้นไปใน `/app` ได้แก่ `server.js`, `app.js`, `validation.js`, `package.json`, `package-lock.json` โดยเก็บ `.env` เดิมไว้ จากนั้น:

```sh
cd /app
npm ci
node server.js
```

ถ้าตัวเก่ากำลังทำงานใน PuTTY ให้หยุดด้วย Ctrl+C ก่อนเปิดตัวใหม่ Backend จะใช้ PORT เดิมหรือค่าเริ่มต้น 3012

ตรวจสถานะที่ `http://119.59.102.161:3012/api` หลังอัปเดตต้องเข้าสู่ระบบใหม่เนื่องจากรูปแบบ token เปลี่ยน

## เปิดหน้าจอแอป

ในโฟลเดอร์ frontend:

```sh
npm ci
npm start
```

เปิด Expo Go บน Android แล้วสแกน QR จาก npm start หรือใช้ npm run android สำหรับ emulator ที่ติดตั้งไว้ แอปใช้ React Native components กับ StyleSheet และ Expo Router ไม่ใช้ไฟล์ HTML หรือ CSS เป็นซอร์สหน้าจอ

API เริ่มต้นชี้ไปเซิร์ฟเวอร์จริงแล้ว หากต้องการ URL อื่น สามารถกำหนด EXPO_PUBLIC_API_URL ตอนเปิดแอป โดยไม่แก้ .env

## ตารางที่ใช้

`users`, `categories`, `incomes`, `expenses`, `budgets`, `saving_goals`, `ai_insights`

ไม่ใช้ตารางสินค้าเดิม `user`, `Products`, `ProductClusters` และไม่ลบตารางเหล่านี้ เพื่อเก็บข้อมูลเดิมไว้

- สมัครสมาชิก/เข้าสู่ระบบด้วยอีเมล เก็บรหัสผ่านเป็น bcrypt hash
- รหัสผู้ใช้และหมวดหมู่สร้างในโปรแกรมพร้อมล็อกการจัดสรร ID จึงรองรับตารางที่ยังไม่มี AUTO_INCREMENT
- รายรับ–รายจ่ายแยกตามผู้ใช้และเดือน ตรวจหมวดหมู่และประเภทก่อนบันทึก
- งบรายหมวดเดือนเดียวกันตรวจและแก้ไขรายการเดิมภายใน transaction ไม่สร้างรายการซ้ำจากการใช้ API
- เป้าหมายออมเก็บชื่อ จำนวนเงิน และกำหนดเวลา ตามคอลัมน์ที่มีอยู่ ยังไม่มีการเก็บยอดออมสะสมหรือประวัติการฝาก เพราะตารางเดิมไม่มีฟิลด์เหล่านี้
- สรุปการเงินอัตโนมัติจากกฎ เก็บใน ai_insights ยังไม่ได้เชื่อมโมเดล AI
- ข้อมูลบัญชี รายรับประจำที่คาดไว้ และเป้าหมายงบรวม ค่าที่ตั้งไว้ไม่บวกเป็นรายรับจริง

หาก categories ยังว่าง ให้เพิ่มหมวดจากหน้าบันทึกรายรับ/รายจ่ายด้วยปุ่ม “เพิ่มหมวดหมู่” โปรแกรมไม่เติมข้อมูลเริ่มต้นให้เอง

## ความสัมพันธ์

Backend ตรวจผู้ใช้และหมวดหมู่ ล็อกผู้ใช้/หมวดที่เกี่ยวข้อง และใช้ transaction ก่อนบันทึก การลบผู้ใช้ถูกปฏิเสธเมื่อมีข้อมูลอ้างอิง การลบหมวดตรวจรายรับ รายจ่าย และงบของทุกผู้ใช้ก่อนลบ พร้อมตรวจรหัสผ่านของผู้ขอลบ หมวดเป็นส่วนกลางตามโครงสร้างเดิม

การแก้ข้อมูลตรงผ่าน phpMyAdmin ข้ามการตรวจใน Backend ได้ ฐานข้อมูลเดิมไม่มี Foreign Key

## ตรวจสอบโค้ด

```sh
# backend
npm test
# frontend (หลังเปิด Expo เพื่อสร้าง route types)
npm run typecheck
npm run check:android
```

การทดสอบ Backend ใช้ฐานข้อมูลจำลอง ไม่เขียนข้อมูลจริง ถ้ารัน Backend บนเครื่องนี้และ DB_HOST ชี้ผ่าน SSH tunnel ต้องเปิด PuTTY/tunnel ก่อน ส่วน Backend บนเซิร์ฟเวอร์ใช้การเชื่อมต่อของเซิร์ฟเวอร์ตาม .env เดิม
